## Human procedure fixed before outputs

One or more consenting independent reviewers complete all three pairs; report each reviewer separately. Seed order is 2, 4, 8. First arm is rules/model/rules respectively. Operator assigns opaque A/B labels and keeps the mapping out of the review packet; it is revealed after scores are locked. With three pairs, order cannot be perfectly balanced; this and possible carryover are explicit limitations.

For each arm, allow eight minutes: World -> select Spark 1 -> Follow -> checkpoint 40 -> personal Chronicle -> cited event/scene -> Return to Live. Ask the reviewer to identify the Spark, describe one recorded choice, describe a supported consequence, and locate its exact evidence. A correct supported answer earns one point per task; absent behavior can be correctly described and must not be invented to earn credit. Record navigation failures separately from content scores and stop causal benefit interpretation if technical hard gates fail.

Immediately collect interest in continuing (1–5), and record evidence-location time in seconds from the evidence task prompt. Hide the history for ten minutes, with no other study history during the delay, then repeat the four recall questions without UI access. Take a five-minute break before the next arm. No hints, arm-specific coaching or substituted episodes. Human answers are scored against public committed records by an operator who documents ambiguous answers; knowing the arm during scoring is reported as bias risk. No model judges.

Primary score is immediate explanation correctness (0–4). Delayed recall, interest and evidence-location time are separate secondary outcomes. Use the S002 threshold: median paired immediate-score improvement >=1, improvement on >=2 seed pairs, and all technical gates passing. Report raw per-pair results, ties, unsupported claims and regressions. No human review means all human metrics remain unmeasured. Three pairs cannot establish population benefit or authorize rollout.

## Technical gates and commands

Build first with `npm run build`. Run `node scripts/model-study-protocol.mjs` to reject manifest/source/bundle/fixture drift and repeat all three rules-only fixtures. Do not use `--freeze` to suppress a failed check; it is an explicit preregistration-authoring operation requiring review and a new version after any study output exists.

Run `npm run test:model-study` (after building) for durable pre-dispatch reservations, uncertain charges, per-seed/total caps, single ownership, concurrency, UTF-8 limits, kill, timeout and deadline behavior. All transports in this suite are synthetic and make no network calls. Reservation amounts are integer micro-USD and never released automatically, even on success. A lock deliberately blocks restart after crashes or closure; reconciliation is manual and cannot erase prior attempts or charges. The supervisor kills only its newly forked worker, including a synthetic worker with a blocked event loop. It strips inherited provider credentials from the worker environment. The integrated transport adds a separate watchdog process per request: it owns the fixed worker, kills blocked workers on deadline, and kills the worker when the runner IPC channel closes. Tests terminate the runner process and verify its worker disappears. Worker errors are fixed sanitized messages. No subprocess inherits provider credentials; a future approved live credential is passed only by private IPC.

Run the built engine suites `first-glow-context.test.js`, `first-glow-history.test.js`, `first-glow-hybrid-runtime.test.js`, `first-glow-staging-effects.test.js`, and `first-glow-interpretations.test.js` under `packages/engine/dist/` for knowledge boundaries, historical identity, provider-free playback and authority/validation. These synthetic regression gates are distinct from S001 UI/human acceptance and real provider behavior.

The study adds a second eligibility filter over the older attention allowance: an outbound request must match an already-recorded created RC slot for that actor/pulse, at most once per Spark per 64-pulse day. It never creates scheduler decisions or Heroes. Missing slots produce rules fallbacks and explicit RC-suppression journal entries, not provider failures or artificial replacement encounters. A zero-request natural sample is a valid finding. A changed RC policy stops the study.

The integrated suite exercises the actual adapter serialization, durable reservation before worker dispatch, invalid/missing usage, hidden evidence, oversized wire input, crash and timeout without retries, restart rejection, parent-loss cleanup, and all six ordinary-play synthetic arms, with both arms using the same staging path. The guard retains the full worst-case request allowance even when the adapter's older telemetry reports zero cost. Local synthetic price fixtures verify integer upper-bound arithmetic; they do not establish current provider prices.

`model-study-runner.mjs` verifies the frozen source manifest before opening a ledger. Synthetic mode is the default and never calls fetch. Live API admission requires an owner-approved S004 packet bound to the exact protocol hash, absolute run directory, account/project/model/region, S001 acceptance, privacy/retention and pricing verification, a <=30-minute execution window, explicit prior cost allocation, and conservative per-request input/output/fee bounds. It rejects absent approval before creating a worker. The CLI deliberately exposes synthetic execution only: `node scripts/model-study-execute.mjs <new-isolated-directory>`.

S004 still needs real account-specific terms/prices, approved input token bounds including all billable usage, a final source/approval packet and human-review arrangements. An abort or killed worker cannot prove a remote provider stopped billing; no reservation is released automatically. A lost watchdog process is outside the tested single runner-parent-loss fault model; the worker request is also bounded by the approved server/model output contract, but no broader fault-tolerance claim is made.

## Recording and decision

Use isolated `.tmp/model-study/<run-id>/` paths; never the normal local database or hosted world. Keep an immutable run manifest, reservations and sanitized result receipts with source/protocol hashes. The runner fsyncs a per-pulse journal of actual events, interpretations and accepted/rejected transitions, saves final or interrupted state, and retains incomplete arm status. It does not replace failed runs. These private synthetic histories are not public telemetry. Execute only after S001 disposition, S003 control readiness and explicit S004 manifest-specific owner approval. Preserve the controls' data retention and redaction rules.

Technical results are pass/fail/blocked; human outcomes are measured/unmeasured; model benefit is exploratory/defer. These axes cannot substitute for each other. Failed or incomplete runs are retained without replacement, new calls or automatic budget reset. S005 records the ultimate recommendation separately.
